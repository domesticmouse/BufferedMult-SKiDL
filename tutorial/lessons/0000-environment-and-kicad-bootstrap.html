Environment, uv & KiCad 10 Bootstrap

Configure a deterministic Python 3.14 + SKiDL environment with uv, point SKiDL at KiCad 10's local symbol and footprint libraries before import time, and run a zero-warning ERC() smoke test.

✓ ERC: 0 Errors, 0 Warnings ✓ Ruff: Clean App: ./apps/0000-environment-and-kicad-bootstrap/

Why the Top 20 Lines of buffered_multiple.py Matter

Since you already know how analog Eurorack circuits work—±12V rails, local 100nF decoupling caps, and op-amp followers—our first job is making sure Python and SKiDL can reliably find KiCad 10's component libraries and run Electrical Rules Checking (ERC()) without environment hiccups.

If you open buffered_multiple.py at lines 26–58, you will notice that os.environ is configured before from skidl import .... That ordering is deliberate:

1. Creating the uv Virtual Environment (Python 3.14)

SKiDL depends on inspice → h5py. Bleeding-edge unreleased Python builds often lack prebuilt binary wheels for h5py and fail trying to compile libhdf5 from C source. Targeting Python 3.14 with uv venv --clear guarantees fast, prebuilt binary wheel installation:

2. Pre-Import Environment Variables & # noqa: E402

The moment Python executes from skidl import ..., SKiDL immediately initializes its global SkidlConfig singleton and imports matplotlib. During that import, two things happen:

  1. Cache directories: SKiDL and Matplotlib try to create ~/.local/share/skidl (or ~/Library/Application Support/skidl) and ~/.matplotlib. Setting XDG_DATA_HOME and MPLCONFIGDIR to /tmp/... before import prevents permission errors in restricted shells or CI runners.
  2. KiCad 10 symbol & footprint discovery: In SKiDL, the default tool KICAD aliases KICAD10. On macOS, KiCad 10 bundles its symbols and footprints inside /Applications/KiCad/KiCad.app/Contents/SharedSupport/, but does not export KICAD10_SYMBOL_DIR to your shell profile automatically. Setting KICAD10_SYMBOL_DIR, KICAD_SYMBOL_DIR, and KICAD10_FOOTPRINT_DIR before importing skidl ensures SKiDL resolves every symbol on the first try.
Why # noqa: E402 is on the from skidl import ... line

Python's linter (ruff rule E402) normally flags module imports that appear after executable statements like os.environ.setdefault(...). Adding # noqa: E402 on the from skidl import ... line tells ruff that the pre-import configuration is intentional.
